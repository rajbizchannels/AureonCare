### M10 — Medical camps

```
A health camp is a clinic that moved for the day.

The records almost never move with it. There is a table at the gate, a paper register, and a box of forms that somebody types up three weeks later — minus the ones that got rained on.

We shipped medical camps this month. Four parts, in the order the day actually happens:

Plan — services, staff, stations, supplies. When you roster a clinician who already has clinic appointments inside the camp window, it lists them before anyone is committed. A camp takes people away from the practice, and pretending otherwise is how Tuesday falls apart.

Desk — a walk-in with no appointment and no file becomes a queue token and a real record, at the gate, in about fifteen seconds.

Board — every station live, with the longest wait at each. When fourteen people are stacked at the doctor and nobody is at vitals, you can see it and move someone.

Outcomes — how many were seen, how many became patients, how many booked a follow-up. That last number is the one that decides whether the camp pays for itself.

And the sponsor report is counts only. No names, no dates of birth, and small groups combined so a single case cannot identify anybody.

```

### M11 — Locations

```
The day you open a second site, every number in the system needs a qualifier.

Which site. Whose patients. Which room. Most systems answer that with a free-text address field and hope.

Locations shipped this month: a site is now a real thing the rest of the product points at. Clinics, camp venues, mobile units, partner premises — all the same kind of object, which is the bit that matters. A community hall you do not own is a site in exactly the way the surgery is, so outreach stops growing its own parallel address book.

One site is primary, and anything not assigned to a site belongs to it. So nothing is stranded while the second site is still being set up.

Deactivating a site removes it from every picker without rewriting the history that already references it.

[ M11 LINK ]
```

### M12 — Specialty setup

```
Every practice management system starts the same way: generic. Every module switched on, no services, and a week of typing before it looks anything like the practice using it.

So we built a setup wizard. That part is unremarkable — most vendors have one.

Here is the part that is not. Nothing is written until the final step, and the preview tells you exactly what will change: what it will create, what is already there, and what it refuses to touch.

That last column is the feature.

If you changed the annual physical to forty minutes, it stays forty minutes. If your price for a well-child visit differs from the pack's, yours wins. The pack reports the difference and then leaves it alone — and a later update will not quietly restore the vendor's version over yours.

Anyone who has had an "update" hand back a year of local configuration knows why that column exists.

[ M12 LINK ]
```
